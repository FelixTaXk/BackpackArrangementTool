# 求解引擎 + 游戏主题 UX 设计文档

## 总览

本项目当前**只使用元启发式 SA 引擎**（老 DFS 引擎 `solver-worker.js` 已退役并删除）。SA 引擎融合并超越竞品的全部关键技术：

| 维度 | 竞品 | 本设计 |
|---|---|---|
| 邻域选择 | 固定 45/30/25 | **ALNS 自适应算子轮盘赌**（段式记分动态调权） |
| 并行协作 | 岛模型中心广播 | **并行回火 Replica Exchange**（对偶准则交换，去中心化，可降级） |
| 增量评分 | 重算受影响件 | **成对加性 CSR 对表**，delta 仅 O(形状周长)，戳去重零分配 |
| 位板 | Int16Array 扫格 | **Uint32Array(L) 位板**（L=2，42 格），冲突一条 AND |
| LNS 上界 | 分数背包+连通空区 | 分数背包+**配对感知加成松弛**+连通空区（零 BigInt 重写） |
| 目标语义 | 复合分近似填满优先 | **真字典序复核闸门**（complete>总属性>手动向量>默认向量>邻接>件数>面积） |
| 可复现 | 无 | **种子 RNG 可复现**（同 seed+payload 可复现） |

正确性架构原则：**热路径快算、晋级全算**——SA 内部用标量能量驱动搜索，但任何对外 incumbent 必须经共享全量评估器重算 + 主线程 `compareSolverBest`（solver.js）真字典序复核。加成语义：仅同属性法宝之间产生 provider/self 加成事件（分项 stats×rates）。

## 文件规划（当前结构）

- `js/score-shared.js`：评分纯函数层（scorePairBonusEvents / scorePotentialPairBonus / scorePriorityGainFor / scoreEvaluateConcrete / scoreSerializeBest 等），黄金样例自测 `window.__SCORE_SELFTEST__`。
- `js/engine-encoding.js`：SoA 编码 + CSR 对表构建 + 主线程结果重建（Transferable ArrayBuffer 束）。
- `js/engine-worker.js`：`engineWorkerMain()`（SA+ALNS+回火+LNS）+ `createEngineWorker()`（Function.toString 拼装 Blob，挂 `_blobUrl`）。
- `js/engine-orchestrator.js`：Worker 编排、回火 broker、SA incumbent/done 消息契约转换。
- `js/solver.js`：求解编排（物品准备/Worker 生命周期/心跳/取消/比较/入口），统一调用 `engOrchCreateWorkers` 走 SA。
- `js/ui-*.js` + `css/styles.css`：渲染与《我要当老祖》主题 UX。

> 历史备注：老 DFS 引擎 `solver-worker.js` 及 `engineMode` 下拉（legacy/hybrid/auto）已于后期**整体退役并删除**，不再保留双引擎对比路径。

## 核心数据结构（engine-encoding.js）

位板：`Uint32Array(L)`，L=ceil(W*H/32)=2；冲突 `(occ[k]&p[k])===0 ∀k`。
Placement SoA：`plMask/plNbr Uint32Array(P*L)`、`plItem Uint16Array`、`plArea Uint8Array`、`plCellsOff/Len`+`cellsFlat`。
Item SoA：`itemValue/itemStats(I*K)/itemRates(I*K) Float64Array`、`itemKind Uint8Array(0 none/1 provider/2 self)`、`itemManual Int16Array`、`itemTier Int8Array`、`itemPlOff/Len`。
**CSR 对表**（成对加性地基，仅存几何可相邻的 placement 对）：`adjOff`、`adjPeer`、`adjBonus`（=potentialPairBonus 精确值）、`adjMan/adjDef`（位压缩优先级向量增量）。规模：deg≤周长≤12，P≤1800 时 Σdeg≤2 万，<500KB。
运行态（预分配、稳态零分配）：`occ Uint32Array(L)`、`cellOwner Int16Array(42)`、`solPl Int32Array(I)`、`touchStamp Int32Array(I)`+纪元、xorshift128+ 种子 RNG。

## 增量 delta 公式（engine-worker.js 热路径）

```
deltaFor(pIdx, sign):            // O(周长)，戳去重同件多格相邻
  stampEpoch++
  for e in adj 区间(pIdx):
    q=adjPeer[e]; if solPl[plItem[q]]<0 或 同件已戳: continue
    戳记; dAdj+=sign; dBonus+=sign*adjBonus[e]; dManW/dDefW+=sign*解码(adjMan/adjDef[e])
applyMove(it,pNew): 先 undoDelta(solPl[it])，再位板 OR+cellOwner 写+addDelta(pNew)；回滚=反向执行
```

## SA+ALNS 主循环

初始解：价值密度+rng 扰动贪心。ALNS 算子 `relocate / moveGreedy / swapPair / removeInsert / shuffleRegion`（一期）+ `lnsSmall/lnsBig`（二期，LNS 默认关闭，隐藏开关 `window.__ENGINE_LNS_ON__` 开启）；每 SEGMENT=256 迭代动态调权，轮盘赌前缀和。
接受：Metropolis（exp 查找表免 Math.exp）；温度几何分层 `T_i=T0*0.85^i`，4 周期重热。
晋级：能量超最优时从 solPl 重建 placements → `scoreEvaluateConcrete` 全量重算 → orchestrator 序列化 best → 走 incumbent 路径实时渲染。

## 并行回火协议（engine-orchestrator.js）

默认档（file:// 兼容）：Worker 定期发 `{type:'swap-req', sol:Transferable Int32Array}` 后不等待继续迭代；主线程 broker 对相邻温度对奇偶轮按 Metropolis 准则配对，transfer 回发。增强档：检测 `crossOriginIsolated` 启用 SharedArrayBuffer+Atomics（SAB 直连）。隐藏开关 `window.__ENGINE_TEMPERING_OFF__`/`__ENGINE_SAB_OFF__` 可整体禁用。

## 期 4：《我要当老祖》主题 UX

水墨修仙风（宣纸木牌 + 书法匾额 + 朱砂鎏金），与通用扁平卡片完全错位。令牌化 CSS 变量、毛笔匾额页头、羊皮纸面板、灵枢宝鉴式圆形属性罗盘筛选、品质卡色、结果格按属性染色。详见 `css/styles.css` 顶部令牌与既有页面。

## 属性模型

参与计算的基础属性注册表 `bonusStats`：atk（攻击力）/ def（防御）/ hp（生命值），加成率即百分比数值。Excel 中的额外战斗加成（伤害 / 暴击伤害 / 治疗效果 / 护盾值 / 汲取）与共鸣值 / 种类存于 `extraRates` / `extraStats`（不参与计算）。`是否造成伤害`（`causesDamage`）标记由 E 盘 Excel 转换时解析（是/1/true/y/yes → true），供「伤害加成」目标标记。

## 验收指标

| 指标 | 目标 |
|---|---|
| 单 Worker 迭代速率 | ≥15 万/秒（n≤20） |
| 3 秒解质量 | 对比人工基线可接受；完整装入率优先 |
| 明细对账 | ΣbonusEvents.bonus === bonusScore；statTotals 分项对账 |
| Portfolio | 并行结果 ≥ 单 Worker 成员 |

## 风险与缓解

- **标量能量碰撞字典序**：量级间隔按可证上界设定；incumbent 必过真字典序复核器。
- **GC 回归**：热路径禁对象分配（TypedArray+戳+exp 表）。
- **Worker 生命周期**：新 Worker 进同一 solverWorkers 数组，cleanup/cancel/onerror 零改动覆盖；`_blobUrl` 必挂。
- **file:// 无 SAB**：默认 broker 全场景可用。
- **主题 UX 可读性**：书法字体仅用于标题/牌匾，正文与数字用圆黑+等宽数字；对比度 AA。
